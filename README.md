## Stack

- **HTML/CSS/JS** — Bootstrap 4.3.1, jQuery 3.4.1, Fancybox 3.0.11, Font Awesome Free 5.10.2
- **PHP** — vendored PHPMailer 5.2.28 for contact/mailing-list submissions, reCAPTCHA v2 (invisible)
- **Build** — esbuild via `build.mjs` (bundles + minifies JS and CSS into `src/dist/`)
- **Tests** — Playwright (Chromium + Firefox) against a local `http-server`; 79 tests per browser
- **CI/CD** — GitHub Actions: build, test, deploy via lftp SFTP on push to `master` or `staging`
- **Analytics** — Google Analytics 4 (`G-HE9ZHJ520Q`) in `<head>`, event tracking via `src/js/analytics.js`, Microsoft Clarity on the homepage

## Key features

### Interactive world map

The "Where We Work" section fetches `img/world-map.svg`, injects it into `#farms-map-container`, and
highlights the configured countries. The map is defined in `src/js/world-map.js`.

To add or remove highlighted countries, edit the `regions` array at the top of `world-map.js`. Each
region has a `name`, an array of ISO 3166-1 alpha-2 `codes`, and label coordinates (`labelX`, `labelY`).
The SVG source was generated from Natural Earth 110m data and contains paths for 177 countries
identified by alpha-2 code; 26 are currently highlighted across 5 regions.

Features: hover tooltips with country names, smooth highlight transitions, responsive scaling, and a
`<noscript>` fallback to a static PNG. Full behavior — including tooltip positioning and clamping — is
documented in [docs/functional-spec.md §2.6](docs/functional-spec.md#26-where-we-work-projects-bg-light).

### Analytics event tracking

Events are tracked via `data-track` attributes — no inline `onclick` handlers. The gtag snippet is in
`<head>` on all pages, ensuring `gtag()` is defined before the bundle executes.

| Attribute | Value | GA4 Event | Key Parameters |
|---|---|---|---|
| `data-track` | `donation` | `donation_click` | `link_text`, `link_url` |
| `data-track` | `pdf` | `file_download` | `file_name`, `file_extension`, `link_url`, `link_text` |
| `data-track` | `outbound` | `outbound_click` | `link_url`, `link_domain`, `link_text`, `outbound` |
| `data-track` | `newsletter-signup` | `sign_up` | `method` |
| `data-track-label` | any string | — | overrides the default label |

Video play events (`video_play`) are tracked via the Vimeo Player API and the YouTube iframe API — not
via click handlers on wrapper divs, which cannot capture cross-origin iframe interactions.

`farms.js` also attempts to fire `form_submit` after a successful AJAX submission, but that call is
currently a no-op — see [docs/known-issues.md](docs/known-issues.md#ki-01).

GA4 Enhanced Measurement handles generic outbound link tracking automatically. The explicit
`data-track="outbound"` is for curated links where a custom `outbound_click` event with specific labels
is wanted.

### `brand-guide.html`

Developer-only reference for the site's color palette, typography, and UI components. Excluded from
CI/CD deployment and does not include Google Analytics. Do not link to it from any live page.

## Local development

**Prerequisites:** Node.js 24+ (PHP is only needed on the server for form handling)

```bash
npm install
npm run build      # bundle JS + CSS -> src/dist/  (required before dev/test on a fresh clone)
npm run dev        # static server on src/ at http://localhost:8080 (no watch — re-run build after edits)
npm test           # run Playwright tests (headless, Chromium + Firefox)
npm run test:ui    # run Playwright tests with UI
```

Tests automatically start `http-server` on `src/` at port 8080. The dev server is static, so `.php`
files are served as text; form submissions can only be exercised on a PHP host.

## Deployment

Deployment runs automatically via GitHub Actions on every push to `master` (production) or `staging`,
gated behind passing tests.

**First-time setup:**
1. Copy `src/config.example.php` to `src/config.php` on the server and fill in credentials
   (`smtpemail`, `smtppassword`, `smtpserver`, `mailto`, `recaptchaprivatekey`)
2. Set these GitHub repository secrets:
   - `DEPLOY_HOST` — SFTP hostname (e.g. `farmsinternational.com`)
   - `DEPLOY_USER` — SFTP username
   - `DEPLOY_PASSWORD` — SFTP password
   - `DEPLOY_PATH` — remote web root for production
   - `DEPLOY_PATH_STAGING` — remote web root for the staging environment

The deploy step uses `lftp` to mirror `src/` to the server via SFTP with `--delete`, excluding
`.git`, `.DS_Store`, `config.php`, `error_log.txt`, and `brand-guide.html`.
